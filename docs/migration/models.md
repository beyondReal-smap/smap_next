# 모델 ↔ 테이블 매핑 (SQLAlchemy → GORM)
> 총 **14개 모델**. Python/Go가 동일 테이블을 공유(단일 소스 오브 트루스).

> ⚠️ **동시점유 위험**: 현재 Go 백엔드(/data/wwwroot/smap_next/backend-go)는 스캐폴드 단계로 GORM 모델/테이블 정의가 아직 없음(health/cache/middleware/db/config/server/observability만 존재) — 따라서 지금 시점의 실제 동시 쓰기 충돌은 없음. 아래는 Go 모델 이식 후 발생할 경합 위험을 Python 측 쓰기 패턴(모델 메서드/스케줄러)으로부터 추정한 것임.\n\n[최고 위험 — 고빈도 INSERT/UPDATE 동시 점유]\n1. member_location_log_t (MemberLocationLog): GPS 위치 로그 append-only 고빈도 INSERT. Python 위치 수집 + Go 위치 수집이 동시 쓰면 PK autoincrement 경합/락 대기 가능. 단 append-only라 행 단위 충돌은 적음. mlt_idx MAX 서브쿼리 조회는 양측 동시 실행 시 일관성 주의.\n2. smap_chat_msg_t (ChatMessage) / smap_chat_member_t (ChatMember): 채팅 메시지 INSERT와 scm_last_read_idx 읽음 커서 UPDATE가 양 백엔드에서 동시 발생하면 last_read 단조증가 가정이 깨질 수 있음(lost update). WebSocket이 어느 쪽에서 처리되는지 단일화 필요.\n3. push_log_t (PushLog) / push_fcm_t (PushFCM): 스케줄러가 예약 푸시 스캔(plt_status=1, plt_sdate<=now / pft_rdate 정시) 후 상태 갱신. Python 스케줄러와 Go 스케줄러가 동일 행을 동시에 집어 발송하면 중복 푸시 발송 위험(가장 실질적 위험). 스케줄러는 반드시 한쪽에서만 구동하거나 SELECT ... FOR UPDATE/상태 CAS 필요.\n\n[중간 위험 — 상태 플래그 동시 갱신]\n4. member_t (Member): mt_token_id/mt_token_updated_at(FCM 토큰 갱신), mt_ldate/mt_adate(접속 시각), mt_status/mt_level 등 상태 컬럼을 양측이 갱신하면 lost update. 광범위하게 참조되는 핵심 테이블이라 동시 점유 시 영향 큼.\n5. smap_group_detail_t (GroupDetail): discharge/exit/show 3중 상태 컬럼 갱신이 역할/탈퇴 로직과 얽혀 race 시 그룹 멤버십 불일치 가능.\n6. smap_location_t (Location): slt_enter_chk(진입 상태) 갱신을 위치 알림 잡이 갱신 — 스케줄러 이중화 시 중복 진입/이탈 알림.\n\n[낮은 위험]\n7. smap_group_t/smap_schedule_t: 사용자 액션 기반 갱신이라 동일 행 동시 쓰기 빈도 낮음. refresh_tokens: token_hash UNIQUE라 충돌 시 DB가 거부(안전). order_t/notice_t: 쓰기 빈도 낮음, notice nt_hit 조회수만 동시 증가 경합 가능.\n\n[공통 주의] 시간대 불일치: Member/Schedule/Location은 datetime.now()(로컬), Group(soft_delete)/Chat 계열은 datetime.utcnow()(UTC) 혼용 — Go 이식 시 한쪽으로 통일하지 않으면 양 백엔드가 같은 컬럼에 다른 기준 시각을 써서 정렬/만료 판정 오류 발생. autoincrement PK를 양측이 공유하므로 ID 채번은 DB에 일임(앱 측 채번 금지).

## SQLAlchemy relationship
- **Group**: GroupDetail와 sgt_idx로 join(명시적 relationship() 없음, 쿼리 레벨 join)
- **GroupDetail**: Member와 mt_idx로 join(쿼리 레벨, find_owner/find_leader/get_member_list)
- **Location**: Member와 mt_idx로 raw SQL join(get_in_myplays_list)
- **Schedule**: GroupDetail와 sgdt_idx로 outerjoin(find_by_group, mt_schedule_idx 라벨 주입)
- **ChatRoom**: ChatMember와 scr_idx로 join(get_rooms_for_member, find_dm)
- **ChatMember**: ChatRoom/ChatMessage와 scr_idx 연결(쿼리 레벨)
- **ChatMessage**: ChatRoom과 scr_idx 연결, count_unread는 ChatMember 참조
